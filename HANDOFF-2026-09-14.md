## Run -04 failed its own gate, not the render

`cloud-v12-l4-20260914-04` rendered correctly (exit 0, OptiX armed, CPU
disabled, 238.5 s render, negative control passed) but was marked failed by
`NO_BLENDER_GPU_PROCESS_EVIDENCE`. Root cause: `nvidia-smi
--query-compute-apps` inside Modal's PID-namespaced container reports the
compute application as PID 1 under the init binary's name, `/bin/dumb-init`,
so the harness's substring match on "blender" can never succeed there. The raw
samples show the real story: one sole compute app ramping 10 → 814 MiB,
peaking at 1,642 MiB, holding 814 MiB across the whole render window —
Blender's OptiX context attributed to PID 1.

`gpu_process_evidence()` in `scripts/cloud_parity.py` now accepts a compute
app named blender **or** a sole compute app holding at least `MIN_SOLO_GPU_MIB`
(256 MiB; this payload's OptiX context holds 814 MiB sustained and the headless
container runs no other GPU apps). Five focused tests cover it; the full suite
is 73 tests, exit zero.

`comparison.json` in -04 was computed afterwards with the same `compare()` the
normal flow runs, on the hash-verified downloaded artifacts; its `status.json`
still says `failed`, honestly, because that is what the harness that ran it
concluded. The salvage metrics match -05 within GPU run-to-run noise (the
linear RGB MAE differs in the eighth significant digit between two identical
L4 renders — digests differ run to run; the tolerance gate is the contract,
never digest equality, now demonstrated on identical hardware).

## Cloud facts worth not re-deriving

- **nvidia-smi in containers lies about names.** PID 1 + `/bin/dumb-init` is
  the container's only truthful answer; match on memory, not names. This cost
  one full billed run to learn.
- **PowerShell `*>` redirection writes UTF-16 logs.** Cosmetic; the JSON
  evidence files are authoritative. `iconv -f UTF-16LE` reads them fine.
- **Full-suite runs from PowerShell create `scripts/__pycache__`** (the
  PYTHONDONTWRITEBYTECODE guard only covers the Git Bash path). Delete it
  after, and never let a cache land inside a frozen payload directory or
  preflight fails on `UNDECLARED_PAYLOAD_FILE`.
- **Image layers cache across runs** when payload and probe hashes are
  unchanged — -05 rebuilt nothing. Changing the harness does not invalidate
  the image; changing `cloud_blender_probe.py` or any mounted payload does.
- **Run directories are UTC-dated**; the local working date was 2026-09-13.
- The wrapper Python must match the container's Python minor version; Modal's
  `serialized=True` carries it. Already handled in the harness — do not
  "simplify" it away.
