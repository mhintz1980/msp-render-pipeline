Still one node and one fused solid — that has not changed and cannot be worked
around; see [[pump-is-one-fused-solid]]. What *has* changed is the tessellation,
which is the only lever that was ever going to move this. 276,666 triangles is
**42.8%** of the 646,666 currently in the scene, before the weld and dissolve
pass takes another bite.

**Method.** Import it, then put the new mesh where the old one is by copying the
existing object's `matrix_world` onto it. Mark eyeballed that placement by hand
and it is not recorded anywhere else, so it must be carried across rather than
re-derived:

1. Read `PUMP_END_CASTSTEEL-1.matrix_world` from `cad/RL300-SAFE-photoreal.blend`
   (v7 has it at location (−0.0004, −0.7963, 0.8292), rotation 0, scale 1, but
   read it rather than trusting this note).
2. Import the coarse GLB.
3. **Before** relying on the transform, compare the imported mesh's *local*
   bounding box with the old one's. Both are the same CAD part in the same
   coordinate frame, so they should agree to within tessellation error — a few
   tenths of a millimetre. If they do not, the glTF importer's axis conversion
   differed between exports and the transform is not transferable; stop and say
   so rather than placing it blind.
4. Apply the saved `matrix_world`, name it `PUMP_END_CASTSTEEL-1`, parent to
   `PUMP_HOUSING`, link into the `Collection` collection.
5. Delete the old pump object and its mesh.
6. Verify the *world* bounding box matches the v7 pump's (336.6 × 1169.9 ×
   563.0 mm, centred so it spans Y −1238.2 to −68.3 and Z 572.2 to 1135.1 mm).

`reduce_pump()` in the edit script then welds at 1 µm and dissolves at 1° as
before. Expect the weld to close it to zero boundary edges again; if it does not,
the function already prints a warning, and that would mean the new export is no
longer a single closed solid and the reduction reasoning needs redoing.

The manifest rule `^PUMP_END_CASTSTEEL-1$` → `MSP_BLACK_CHASSIS` already exists
and needs no change **provided the name is preserved**. `_reassign_materials`
raises when a rule matches nothing, by design, so a rename would fail loudly
rather than silently un-shade the pump.

## Facts worth not re-deriving

- **`ShaderNodeTangent` radial takes an object-space axis.** `MSP_ALUMINUM_CAST`
  covers four objects that disagree — the 8 in couplings revolve about local Y,
  `V251415K55_Aluminum Cam and Groove Hose Coupling-1` about local X — so the
  anisotropy is scoped to a cloned `MSP_ALUMINUM_CAST_TURNED` carrying
  `anisotropy: 0.4`, `anisotropy_axis: "Y"`. Do not move it onto the shared
  material.
- **A freshly created `bpy.data.objects.new()` has no evaluated `matrix_world`
  until it is in a collection.** Probing it reads the mesh at identity and returns
  a confident wrong answer. Link and parent first, then `view_layer.update()`.
  This bit once already. See [[blender-unlinked-object-matrix-world]].
- **Dimensions in the render log are metres at one decimal.** Small parts all
  print `0.0x0.0x0.0m`. Not a defect signal — see task 2.
- **Visibility culling does not converge on this pump** (59.8% → 32.7% → 16.7% →
  11.0% hidden as the ray step went 30 mm → 5.4 mm). Do not revive it.
- The generator for the fittings is preserved at
  `cad/generators/flanged_camlock_800al.py` — ASME B16.5 Class 150 8 in: 13.50 in
  flange OD, 1.125 in thick, eight 0.875 in holes on an 11.750 in bolt circle,
  9.00 in cam OD on an 8.625 in neck. It is not run by the pipeline.
- **Shade-auto-smooth in the GUI plants geometry nodes.** Any hand-authored part
  Mark brings in may carry a `Smooth by Angle` modifier and a linked
  `geometry_nodes_essentials.blend`, and preparation blocks on it. The script bakes
  and strips it, but expect the same on the next imported part.
- **`bpy.ops.outliner.orphans_purge` does not clear `bpy.data.libraries` in
  background mode**, and duplicate entries pointing at one file invalidate each
  other on removal — snapshot the filepaths, then drain the collection by index.
- Seven external paths always remain after preparation: `LibraryWeakReference`
  entries to the former `RL300-SAFE-webexport-v1.blend`. Expected, documented, and
  cleared by the preparer.
